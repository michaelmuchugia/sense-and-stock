AfriQuant — Phase 2: Data Ingestion Pipeline Super Prompt

MISSION
Make AfriQuant work on live data instead of the prototype arrays. By the end of this phase, three pipelines will be running:

A. NSE closing prices ingest daily via Vercel Cron, scraping nse.co.ke
B. Analyst research ingest manually via a structured JSON file workflow + CLI
C. AfriQuant score recompute automatically after every price ingest, and on demand via an admin endpoint or CLI

This phase does not touch the UI. The frontend still reads from `lib/data/*` until Phase 3. New scores, prices, and analyst targets accumulate silently in the database. If a pipeline breaks, the public site keeps rendering exactly as it does today.

LOCKED DECISIONS (from collaboration prior to writing this plan)

PIVOT (post Step A1): NSE publishes equity prices as PDFs generated by PDFill PDF Editor, which flattens text to vector outlines — zero items extractable by any Node PDF library (unpdf, pdf-parse, pdfjs-dist all return 0 text items). - Exports to CSV via Acrobat or Adobe online (free)
- Drops CSV in ingest/prices/, runs npm run ingest:prices
- Same security model, same per-file processed/failed move, same per-file ingestion_log entry
Phase 2.5 will revisit auto-ingest via vision-model OCR (Claude/GPT-4) or a commercial PDF API.

1. NSE prices come from a manual CSV upload pipeline (was: scrape NSE.co.ke direct). Operator workflow: download PDF, export to CSV via Acrobat, drop in ingest/prices/, run CLI. Same JSON-paste philosophy as research and analyst pipelines.
2. Analyst research uses a JSON paste workflow — operator reads each PDF, transcribes into structured JSON, drops the file into `ingest/research/`, runs `npm run ingest:research`. Automation deferred to a later phase.
3. Score recompute runs inline at the tail of every price ingest, and is also reachable manually via `POST /api/admin/recompute-scores` and via `npm run recompute:scores`.
4. All pipeline work runs in Vercel functions on the existing Hobby plan. Measure runtime first; only split or move to a queue if a real measurement justifies it.
5. Research JSON files reference analysts by `analyst_external_id` (the integer ID from the seed), not by analyst name. Names are fragile to typos; IDs are stable.
6. Processed JSON files are physically moved out of the pending folder (to `processed/` on success, `failed/` on error). Processed-status is not tracked in the DB — the filesystem is the audit trail for now.
7. `ingestion_log` writes one row per pipeline run, not one row per stock. Per-stock failures are listed in the run row's `errorMessage` (truncated to 500 chars).
8. `ADMIN_SECRET` is a distinct env var from `CRON_SECRET`. Different rotation cadence, different blast radius if leaked.
9. New analysts are onboarded via a mirror of the research JSON workflow — drop a JSON file in `ingest/analysts/`, run `npm run ingest:analysts`. See Pipeline B' below. Analyst names users see in the UI are real (the 16 we seeded are real NSE research bylines); Phase 2 adds *real targets* attributed to those analysts and lets you add new analysts as needed.

SECURITY POSTURE — READ BEFORE WRITING ANY CODE
Phase 2 adds three new threat surfaces: an outbound HTTP scraper, an authenticated admin endpoint, and a filesystem-fed CLI. Each gets explicit hardening.

Outbound scraper
- Set a non-spoofed User-Agent that identifies AfriQuant and a contact address.
- Hard timeout per request (5 seconds). Retry on 5xx only, with exponential backoff, max 3 attempts.
- On 4xx, never retry. On 429/503, never retry — bail and let the next cron run try again.
- Cap parallelism to 1 concurrent request to NSE. We are not DDoSing them.
- Do not store raw HTML/CSV bodies anywhere. Parse, validate with Zod, write only the structured result.
- Validate every parsed row against a Zod schema before any DB write. A malformed scrape must fail the run, not corrupt the database.
- Check `robots.txt` once on first run; if scraping is disallowed, abort and switch to manual CSV upload mode.

Admin endpoint
- New env var `ADMIN_SECRET` — same Zod 32-char minimum as `CRON_SECRET`. Distinct value, distinct purpose.
- Same Bearer + `timingSafeEqual` + per-IP rate-limit + `runtime: 'nodejs'` + `dynamic: 'force-dynamic'` pattern as the cron route. Reuse the helpers, do not duplicate.
- Sanitized error responses — never leak DB connection details, stack traces, or partial state.
- `ADMIN_SECRET` joins the env validator in `lib/db/env.ts` so missing/weak values fail at boot, not on first request.

CLI / filesystem
- The research-ingest CLI reads only `research/*.json` — no globbing outside that directory, no following symlinks.
- Every file is validated against a strict Zod schema (`strict: true`, reject unknown keys, reject extra root fields).
- Processed files move to `research/processed/<timestamp>-<original>` atomically. Failures move to `research/failed/`.
- `research/` and `research/processed/` are committed-gitignored — analyst research PDFs and transcribed JSON often have copyright/contractual constraints we don't want pushed to GitHub.
- A failed file does not block successful files — each file is processed in its own transaction.

Per-stock fault tolerance
- Score recompute is wrapped per stock. If one stock's score calc throws (bad data, missing coverage), log it, continue, and report partial success.
- A run that processes 64 of 65 stocks is `status: 'partial'`, not `'failed'`.

What must never happen
- No scraping without a User-Agent.
- No `ADMIN_SECRET` reused as `CRON_SECRET`. They are different secrets with different rotation policies.
- No raw user input (file contents, scraped HTML) reaching SQL without Zod validation in between.
- No catch-and-swallow on the entire batch. Errors are either per-row (logged + continue) or fatal-to-batch (logged + 500 + ingestion_log row).

PIPELINE A — NSE PRICE SCRAPE

Step A1 — Source investigation (the first concrete task of this phase)
Before writing any scraper code, document the source we will read from:
- Visit https://www.nse.co.ke and find the daily price list. Likely candidates: the "Equity Statistics" or "Market Data > Daily Price List" page.
- Open DevTools, inspect the network calls behind that page. Prefer a JSON/CSV endpoint if one exists; fall back to HTML parsing only if necessary.
- Check `https://www.nse.co.ke/robots.txt`. If the daily price list path is disallowed, stop and notify the user; we will switch to manual CSV upload.
- Record the URL, the response shape, and any rate-limit hints in a top-of-file comment in `lib/ingest/nse-scraper.ts`.

If the source is HTML-only, we use a small parsing library (cheerio) and accept the fragility. If it is JSON, we are home free.

Step A2 — Scraper module (`lib/ingest/nse-scraper.ts`)
Exports a single function:

  async function fetchDailyPrices(): Promise<DailyPriceRow[]>

Implementation rules:
- One fetch call to the source URL.
- 5-second timeout via `AbortController`.
- Retry on 5xx (not 4xx, not network errors that aren't retryable) up to 3 times with backoff 500ms, 1500ms, 4500ms.
- User-Agent: `AfriQuant/0.1 (data-ingest; +https://afriquant.example/contact)`.
- Parse response into a candidate row list.
- Validate each row with a Zod schema (`ticker: z.string().min(1).max(10)`, `close: z.number().positive()`, `date: z.string().regex(YYYY-MM-DD)`, etc.).
- Drop tickers we don't have in `stocks` table (don't auto-insert new ones — that is a manual decision).
- Return an array of validated rows.

Step A3 — Persistence (uses existing `upsertPricesBatch` in `lib/db/queries/prices.ts`)
- For each validated row, call `upsertPricesBatch` which uses the `(stock_id, date)` unique constraint to make re-ingestion safe.
- Count `inserted` vs `unchanged` and return both.

Step A4 — 52w high/low refresh
Add a helper to `lib/db/queries/prices.ts`:

  async function refresh52wWindowForStock(stockId: number): Promise<void>

For each updated stock, recompute high_52w and low_52w from the last 365 calendar days in `stock_prices`. Write back to the latest `stock_prices` row (not to `stocks` — the latest price row carries this).

Step A5 — Trigger score recompute inline
Call `recomputeAllScores()` from `lib/ingest/score-recompute.ts` as the last step of the cron handler. Pass the count of updated stocks back into the ingestion_log row.

Step A6 — Log the run
Update `ingestion_log` exactly once per cron invocation:
- source: 'nse_scraper'
- stocksUpdated: count of new+changed price rows
- status: 'success' | 'partial' | 'failed'
- errorMessage: first 500 chars of error if any
- durationMs: total wall time

PIPELINE B — RESEARCH JSON INGEST

Step B1 — JSON contract (`lib/types/research.ts`)
A single file represents a single research report from a single analyst on a specific date covering one or more stocks. The Zod schema is strict — unknown root keys fail validation.

  {
    "analyst_external_id": 1,
    "report_source": "Faida IB Stock Picks May 2026",
    "issued_date": "2026-05-15",
    "targets": [
      {
        "ticker": "SCOM",
        "target_price": 38.50,
        "rating": "Buy",
        "notes": "Ethiopia losses stabilising; Q4 guidance raised."
      },
      ...
    ]
  }

`rating` is constrained to `'Buy' | 'Hold' | 'Sell'`. `analyst_external_id` must exist in `analysts.external_id`. Each `ticker` must exist in `stocks.ticker`. Unknown analyst or ticker fails the file with a clear error.

Step B2 — Loader module (`lib/ingest/research-loader.ts`)
Exports:

  async function processResearchFile(absolutePath: string): Promise<{ok: boolean; targetsInserted: number; error?: string}>

Implementation:
- Read file, parse JSON, validate with Zod.
- Resolve `analyst_external_id` → `analysts.id` and each `ticker` → `stocks.id` (one query each, cached in a Map).
- For each target:
  - Mark existing `analyst_targets` rows with same `(analyst_id, stock_id)` and `is_current=true` as `is_current=false`.
  - Insert the new row with `is_current=true`.
- All operations for a single file run sequentially. We do not wrap them in a transaction in Phase 2 (Drizzle's `neon-http` driver does not support transactions — to be revisited in Phase 3 if we move to the WebSocket/Pool driver).
- Return the count of inserted targets.

Step B3 — CLI (`scripts/ingest-research.ts`)
- Glob `research/*.json` (no recursion, no symlinks).
- For each file:
  - Run `processResearchFile`.
  - On success, move to `research/processed/<YYYY-MM-DD>-<original>`.
  - On failure, move to `research/failed/<YYYY-MM-DD>-<original>` and write a `.error.txt` sibling with the sanitized error message.
- After all files processed, call `recomputeAllScores()` for the union of affected stocks (not the full universe — for efficiency).
- Write one ingestion_log row per file processed (so an operator can see exactly which files contributed to today's load).

Step B4 — Sample input
Ship `research/sample.json.example` (committed) so an operator can copy-paste and edit. Document the rating vocabulary and date format at the top of `lib/types/research.ts`.

PIPELINE B' — NEW-ANALYST INGEST (mirror of Pipeline B)

Step B'1 — JSON contract (`lib/types/analyst-input.ts`)
One file represents one or more new analysts to add to the `analysts` table. Strict Zod, unknown root keys fail validation.

  {
    "analysts": [
      {
        "external_id": 17,
        "name": "Jane Doe",
        "initials": "JD",
        "firm": "Genghis Capital",
        "since_year": 2024,
        "bio": "Junior equities analyst covering banking and energy. Joined Genghis Capital in 2024."
      },
      ...
    ]
  }

Validation rules:
- `external_id` must not already exist in `analysts.external_id`. If it does, the row is soft-skipped via `onConflictDoNothing` so re-running the file is safe.
- `name` is required, 1-255 chars. `firm` is required for production analysts, optional for placeholder entries.
- All fields validated by a Zod schema that mirrors the DB shape.

Step B'2 — Loader module (`lib/ingest/analyst-loader.ts`)
Exports:

  async function processAnalystFile(absolutePath: string): Promise<{ok: boolean; analystsInserted: number; error?: string}>

Implementation:
- Read, parse JSON, validate with Zod.
- For each entry, INSERT into `analysts` with `onConflictDoNothing` on `external_id`.
- Return count of new analysts actually inserted (vs skipped).

Step B'3 — CLI (`scripts/ingest-analysts.ts`)
- Glob `ingest/analysts/*.json` (no recursion, no symlinks).
- For each file:
  - Run `processAnalystFile`.
  - On success: move to `ingest/analysts/processed/<YYYY-MM-DD>-<original>`.
  - On failure: move to `ingest/analysts/failed/<YYYY-MM-DD>-<original>` with an `.error.txt` sibling.
- Write one `ingestion_log` row per file processed with `source: 'analysts_json:<filename>'`.
- This pipeline does NOT trigger score recompute — adding an analyst with zero coverage doesn't change any score. Score recompute happens later when a research JSON ingests targets for the newly-added analyst.

PIPELINE C — SCORE RECOMPUTE

Step C1 — Engine refactor (small, additive — does not break existing code)
The current `calcScore` in `lib/engine/score.ts` imports `ANALYSTS` from `lib/data/analysts.ts`. The DB version cannot do that. We add a thin DB-aware wrapper without touching the existing `calcScore` (which is still used by the mock-data frontend until Phase 3).

  // lib/engine/score-pure.ts  (NEW — pure function, no data imports)
  export function calcScoreFromInputs(
    stock: StockShape,
    coverage: CoverageShape[],
    latestPrice: PriceShape | null,
  ): AQScore { ... }

  // lib/engine/score.ts  (EXISTING — keep as-is for now)
  export function calcScore(stock: Stock): AQScore {
    // unchanged; calls calcScoreFromInputs internally with ANALYSTS-derived coverage
  }

The intent is that calcScoreFromInputs is the canonical algorithm, and both call sites converge on it. Phase 3 will retire the `lib/data/*` imports entirely.

Step C2 — DB-aware wrapper (`lib/ingest/score-recompute.ts`)
Exports:

  async function recomputeAllScores(): Promise<{updated: number; failed: string[]}>
  async function recomputeScoresForStocks(tickers: string[]): Promise<{updated: number; failed: string[]}>

Both:
- Load stocks + coverage + latest price from DB (joined query; ~1-3 round trips total).
- Loop over stocks, build the inputs for each, call `calcScoreFromInputs`.
- Wrap each stock in try/catch — one failure does not abort the batch.
- Upsert into `stock_scores` via the existing `upsertScore` query.
- Return counts and a list of failed tickers.

Step C3 — Standalone trigger
`POST /api/admin/recompute-scores` — calls `recomputeAllScores`, logs to `ingestion_log` with `source: 'score_recompute_admin'`, returns the result.

`npm run recompute:scores` — runs the same function via tsx CLI for local development.

SUCCESS CRITERIA FOR PHASE 2
Phase 2 is complete when every one of these is true:

1. The NSE source URL and response shape are documented at the top of `lib/ingest/nse-scraper.ts`.
2. Hitting `POST /api/cron/ingest-prices` with the correct `CRON_SECRET` fetches today's prices from NSE, upserts them, refreshes 52w windows, recomputes all scores, and writes one row to `ingestion_log`. Total runtime is logged and is under 60 seconds.
3. Re-running the same scrape within the same day inserts zero new price rows (idempotency via the `(stock_id, date)` unique constraint).
4. `stock_scores` has 65 rows after a successful pipeline run. Each row's `calculated_at` is within the last minute.
5. Copying `ingest/research/sample.json.example` to `ingest/research/test-report.json` and running `npm run ingest:research` produces N rows in `analyst_targets`, moves the file to `ingest/research/processed/`, and triggers a partial score recompute for only the affected stocks.
6. A malformed JSON (missing required field, unknown ticker, unknown analyst) fails fast with a Zod error pointing at the offending path, moves the file to `ingest/research/failed/` with an `.error.txt` sibling, and does not touch the DB.
6a. Copying `ingest/analysts/sample.json.example` to `ingest/analysts/new-analyst.json` (with a fresh `external_id` like 99) and running `npm run ingest:analysts` adds the row to `analysts`, moves the file to `ingest/analysts/processed/`, and does not touch any other table. A duplicate `external_id` in the JSON is a soft-skip, not a hard fail (per `onConflictDoNothing`).
7. `POST /api/admin/recompute-scores` returns 401 without `ADMIN_SECRET`, 200 with it. After a 200, `stock_scores.calculated_at` is updated for all 65 rows.
8. `npm run build` passes. All 94 prerendered routes still render. The frontend is visually identical to its current state.
9. Zero hardcoded secrets. `ADMIN_SECRET` is loaded via Zod at boot, fails on missing/weak.
10. A stock that fails to score (deliberately bad fixture) does not break the batch — the other 64 stocks still get scores, and `ingestion_log.status` reads `'partial'` with the failed ticker named in `errorMessage`.

OPEN QUESTIONS (resolved during execution, not before)
- Q1: What exact URL does NSE serve the daily price list at, and what's the response format? Answered in Step A1 by inspection. If we cannot find a sane endpoint, we revert to manual CSV upload and the user uploads each day.
- Q2: Does NSE's robots.txt allow scraping the price list path? Answered in Step A1. If disallowed, we stop and notify, do not proceed with the scraper.
- Q3: If a research JSON references an `analyst_external_id` that does not exist, the file fails validation (good). The operator's recourse is to first add the analyst via `npm run ingest:analysts`, then re-drop the research file. This is the new-analyst flow in production.
